# Контраст текста на кнопках: правила, формулы и типовые ошибки

Самодостаточная памятка. Её можно передать другому чату или разработчику
целиком — она не требует знания конкретного проекта.

Всё ниже выведено на реальном разборе приложения с 6 цветовыми темами, где
измерение показало **71 нарушение контраста**, худшее — **1.06:1** (текст
физически неразличим). Цифры в примерах настоящие, не выдуманные.

---

## 1. Главный принцип

> **Цвет текста на кнопке нельзя задавать «на глаз» и нельзя задавать один раз
> на всё приложение. Он должен выводиться из измеренного контраста с тем
> фоном, на котором текст реально лежит.**

Почему «на глаз» не работает: человек, который подбирал белый текст на
тёмно-фиолетовой кнопке, видит хороший результат. Тот же белый на
светло-золотой кнопке в другой теме даёт 2.85:1 — нечитаемо. Глаз при этом
«привыкает» и перестаёт замечать, особенно на хорошем мониторе.

---

## 2. Формула

Контраст считается по WCAG в два шага.

### Шаг 1. Относительная яркость (relative luminance)

Для каждого канала (R, G, B), приведённого к диапазону 0…1:

```
если c <= 0.03928:  c_lin = c / 12.92
иначе:              c_lin = ((c + 0.055) / 1.055) ^ 2.4

L = 0.2126 * R_lin + 0.7152 * G_lin + 0.0722 * B_lin
```

Коэффициенты неравные, потому что глаз воспринимает зелёный намного ярче
синего. Именно поэтому **неоново-зелёный — самый коварный акцент**: он
кажется «ярким цветом», а по яркости почти белый (L = 0.724).

### Шаг 2. Коэффициент контраста

```
ratio = (L_светлого + 0.05) / (L_тёмного + 0.05)
```

Диапазон: от **1:1** (одинаковые цвета) до **21:1** (чёрный на белом).

---

## 3. Пороги: сколько нужно

| Порог | Кому применяется |
|---|---|
| **4.5 : 1** | Обычный текст — **сюда попадает большинство надписей на кнопках** |
| **3.0 : 1** | Только крупный текст: от 24px обычного или от 18.7px жирного |
| **3.0 : 1** | Границы элементов, иконки, индикаторы (WCAG 1.4.11) |
| **7.0 : 1** | Повышенный уровень (AAA), для обычного текста |

⚠️ **Частая ошибка:** считать любой жирный шрифт «крупным». Жирный 13–15px —
это **обычный** текст по стандарту, и ему нужны **4.5:1**, а не 3.0. Порог 3.0
включается только с 18.7px жирного.

Практический совет: берите **4.5 как рабочую цель**, а 3.0 — как абсолютный
минимум, ниже которого нельзя опускаться никогда.

---

## 4. Правила для кнопок

### Правило 1. Заведите отдельный токен «текст поверх акцента»

В палитре темы недостаточно одного `TEXT`. Нужен отдельный `ON_ACCENT`:

```
TEXT       — текст на фоне/карточке (спокойный фон)
ON_ACCENT  — текст поверх заливки акцентным цветом (насыщенный фон)
```

`TEXT` подбирается под фон приложения и почти всегда **не подходит** для
насыщенной акцентной заливки. Это две разные задачи.

### Правило 2. Белый — не универсальный выбор

Точка перелома выводится аналитически. Приравняем контраст с белым и с
чёрным:

```
1.05 / (L + 0.05) = (L + 0.05) / 0.05
(L + 0.05)² = 0.0525
L = 0.1791
```

> **Если относительная яркость акцента L > 0.179 — берите тёмный текст.
> Если L < 0.179 — светлый.**

Проверка на реальных цветах:

| Акцент | L | с белым | с чёрным | Что брать |
|---|---|---|---|---|
| `#39ff14` неон-зелёный | 0.724 | **1.36** | 15.49 | тёмный |
| `#b8935a` мягкое золото | 0.318 | **2.85** | 7.36 | тёмный |
| `#0f9e51` зелёный | 0.251 | **3.48** | 6.03 | тёмный |
| `#b5657a` розовый | 0.205 | **4.11** | 5.11 | тёмный |
| `#1f7a9e` синий | 0.167 | 4.84 | 4.34 | светлый |
| `#6c5ce7` фиолетовый | 0.166 | 4.86 | 4.32 | светлый |

**Важное следствие:** ровно в точке перелома и белый, и чёрный дают всего
**4.58:1**. То есть у акцента с L ≈ 0.18 запас практически нулевой — 4.5
достигается, но впритык. Если акцент попал в эту зону, лучше подвинуть сам
акцент (сделать темнее или светлее), чем воевать с цветом текста.

### Правило 3. Вместо чистого чёрного/белого — оттенок самого акцента

Чистый `#000000` на кнопке выглядит грубо и «дёшево». Возьмите очень тёмный
(или очень светлый) вариант самого акцентного цвета — контраст почти тот же,
а ощущение фирменного стиля сохраняется.

```
Было:  золото #b8935a + белый #ffffff            → 2.85:1  ✗
Стало: золото #b8935a + тёмно-коричневый #231a09 → 6.02:1  ✓ и в тон теме
Для сравнения, чистый чёрный дал бы 7.36:1 — но выглядит грубее.
```

Практично: умножьте каналы акцента примерно на 0.15, получите стартовый
вариант — и **обязательно измерьте результат**. Точный множитель зависит от
цвета, «на глаз» здесь снова не работает: разница между 6.02 и 7.36 не видна,
а разница между 2.85 и 6.02 решает всё.

### Правило 4. У каждого состояния — свой цвет текста

Кнопка-переключатель имеет минимум два фона:

- **выбранный** сегмент — залит акцентом → нужен `ON_ACCENT`
- **невыбранный** — залит фоном карточки → нужен `TEXT`

Это два разных фона, значит и два разных цвета текста. Один цвет на оба
состояния гарантированно нечитаем хотя бы в одном из них.

### Правило 5. Считайте от фактического фона, а не от предполагаемого

Если у элемента фон «прозрачный», его реальный фон — это фон родителя. Нужно
подниматься вверх по дереву, пока не найдётся непрозрачный цвет. Иначе вы
измеряете контраст с тем, чего на экране нет.

## 5. Ловушки UI-библиотек

Это то, что вообще не видно при чтении кода и стоило больше всего времени.

### Ловушка А. Умолчания библиотеки молча игнорируют вашу тему

Если не передать цвет явно, библиотека подставит **свой** из встроенной
палитры. Он никак не связан с вашей темой.

```
Реально измерено: текст #dce4ee на заливке #979da2 = 2.14:1
Оба цвета — умолчания библиотеки. В теме приложения таких цветов нет вообще.
```

> **Правило: задавайте цвета явно для каждого состояния, даже если умолчание
> «вроде выглядит нормально» в вашей текущей теме.**

### Ловушка Б. Один `text_color` на оба состояния

Многие компоненты (сегментированные кнопки, вкладки) предоставляют **один**
параметр цвета текста на все сегменты сразу. Выбранный сегмент при этом
заливается акцентом — и наследует цвет, подобранный для невыбранного фона.

Это и дало **1.06:1** на неоново-зелёном.

**Решение:** после отрисовки пройтись по внутренним кнопкам компонента и
перекрасить каждую вручную, а также **повторять это при каждом переключении**
— библиотека перерисует заливки, но цвета текста не тронет.

```python
def recolor_segments(widget, selected_value):
    for value, button in widget._buttons_dict.items():
        button.configure(
            text_color=ON_ACCENT if value == selected_value else TEXT
        )
```

### Ловушка В. Проверка одной темы ничего не доказывает

Проверка в теме по умолчанию пропустила все 71 нарушение, потому что тема по
умолчанию была в порядке. **Проверять нужно все темы разом.**

## 6. Готовый код

Переносится на любой язык — это чистая арифметика.

```python
def relative_luminance(hex_color: str) -> float:
    h = hex_color.lstrip("#")
    if len(h) == 3:
        h = "".join(c * 2 for c in h)
    r, g, b = (int(h[i:i + 2], 16) / 255.0 for i in (0, 2, 4))

    def lin(v: float) -> float:
        return v / 12.92 if v <= 0.03928 else ((v + 0.055) / 1.055) ** 2.4

    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)


def contrast_ratio(fg: str, bg: str) -> float:
    """1.0 (одинаковые) … 21.0 (чёрный на белом)."""
    lf, lb = relative_luminance(fg), relative_luminance(bg)
    hi, lo = max(lf, lb), min(lf, lb)
    return (hi + 0.05) / (lo + 0.05)


def readable_on(bg: str, *candidates: str, threshold: float = 4.5) -> str:
    """Первый кандидат, проходящий порог; иначе — самый контрастный.

    Смысл: первым передаётся желаемый «фирменный» цвет, последним — заведомо
    безопасный. Тогда фирменный оттенок сохраняется там, где он читается, и
    автоматически заменяется там, где нет.
    """
    for c in candidates:
        if contrast_ratio(c, bg) >= threshold:
            return c
    return max(candidates, key=lambda c: contrast_ratio(c, bg))
```

Применение:

```python
# Не так — цвет зашит и сломается в другой теме:
label_color = ACCENT_HOVER

# А так — цвет выбирается по факту:
label_color = readable_on(CARD_HI, ACCENT_HOVER, ACCENT, TEXT)
```

Главная ценность: при добавлении новой темы **ничего не нужно перепроверять
руками** — нечитаемая пара просто не сможет появиться.

## 7. Автоматическая проверка

Одной ручной проверки мало: она повторится не при каждом изменении. Нужны две.

**Проверка 1 — палитры (быстрая, без интерфейса).** Для каждой темы
убедиться, что ключевые пары проходят порог:

```
ON_ACCENT на ACCENT
TEXT на BG
TEXT на CARD
MUTED на CARD
```

**Проверка 2 — реальные виджеты (ловит ловушки А и Б).** Обойти дерево
элементов, у каждого взять фактический цвет текста и фактический фон
(поднимаясь через «прозрачных» родителей), посчитать контраст. Обязательно
заглядывать во внутренние коллекции составных компонентов — сегменты и
вкладки часто **не попадают** в обычный список дочерних элементов.

Именно вторая проверка нашла то, чего не видно в коде.

## 8. Чеклист

- [ ] В палитре есть отдельный токен `ON_ACCENT`, а не только `TEXT`
- [ ] Для каждого акцента проверено: L > 0.179 → тёмный текст, иначе светлый
- [ ] Вместо чистого чёрного/белого — тёмный/светлый оттенок акцента
- [ ] Каждое состояние (выбрано / не выбрано / наведение / отключено) имеет свой цвет
- [ ] Ни один цвет не оставлен на умолчание библиотеки
- [ ] Составные компоненты перекрашиваются вручную **и при каждом переключении**
- [ ] Контраст считается от фактического фона, а не от предполагаемого
- [ ] Проверены **все** темы, а не только используемая по умолчанию
- [ ] Цель 4.5:1 для обычного текста; 3.0:1 — только для по-настоящему крупного
- [ ] Проверка автоматизирована и запускается перед выпуском

---

## 9. Короткая выжимка

1. Контраст **считать**, а не оценивать глазом.
2. Порог **4.5:1**; 3.0 только для текста от 18.7px жирного.
3. Белый текст ломается на светлых акцентах: граница — **L = 0.179**.
4. Разный фон → разный цвет текста. Всегда.
5. Умолчания UI-библиотеки не знают про вашу тему.
6. Проверять все темы и автоматически.
